# 02 五元组流表 (Flow Table)

## 功能描述
基于五元组（src_ip, dst_ip, src_port, dst_port, protocol）对报文所属"流"进行
新建 / 查找 / 老化管理，为下游 IPS 决策引擎提供"该流是否已放行/已知恶意"的状态。

## 设计取舍说明
真实商用防火墙常用 TCAM 或大规模 Hash+CAM 混合结构支持数十万并发流。
本项目为原理验证级实现，采用：
- **直接映射 Hash 表**（`hash = CRC16(五元组) % TABLE_DEPTH`，TABLE_DEPTH=256，可综合参数化）
- **4-way 冲突链**（同一 Hash 桶内最多存 4 条流，超出则老化最久未使用的条目 LRU-simplified）
- 老化：每条表项带 `age_cnt`，每次命中清零，后台计时器每 N 周期对未命中表项 `age_cnt++`，
  超过阈值则标记 `valid=0` 回收。

## 接口定义
输入：`lookup_valid`, `key = {src_ip, dst_ip, src_port, dst_port, protocol}` (104bit)
输出：`hit`, `flow_state[1:0]`（00=新流/未知, 01=已放行, 10=已标记可疑, 11=已阻断）,
`flow_idx`（表项索引，供统计/老化管理使用）

控制（AXI4-Lite 配置面）：
- 允许 PS 侧写入/查询/清空指定流表项状态（用于策略下发或人工加白/拉黑）

## 存储结构
- 每表项：`{valid, age_cnt[7:0], key[103:0], state[1:0]}`，共 256 * 4 = 1024 条目，
  使用 BRAM（Block RAM）实现，深度 1024，位宽 ~114bit（可拆分为多块 BRAM）。

## 时序/资源预估
- Hash 计算（CRC16）1~2 级流水线；BRAM 读延迟 1 拍；比对逻辑 1 拍；整体查找延迟约 3~4 拍。
- 资源预估：BRAM 约 2~4 块（36Kb 型号），LUT 约 300~500（Hash+比较逻辑）。

## 已知简化/取舍
- Hash 冲突处理为简化 4-way，非真实 CAM，理论上限存在冲突丢弃风险，已在文档中如实说明。
- 未实现流表项的持久化/掉电保存（无必要，纯运行时状态）。
